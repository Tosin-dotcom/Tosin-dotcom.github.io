About

Software engineering, taken seriously from end to end.

Good software is invisible when it works and painfully obvious when it doesn't. I care about the first kind.

That means going deep wherever the problem lives tuning a slow query until it stops being the bottleneck, hardening a fragile API so it holds up under real use, polishing an interface until it feels effortless instead of merely functional. My experience spans diverse areas of software development, backend systems, databases, APIs and the interfaces people actually touch and I move across all of them by choice, not necessity. I'm not interested in code that just works for now; I want it to still make sense to whoever touches it next, months down the line.

I think in systems, not isolated tasks. A change rarely stays where you put it. It ripples outward, and part of the job is seeing that ripple before it becomes a problem instead of after. So I don't wait to be told something needs fixing, refactoring, or rethinking; I notice it and act on it, the same way I'd want someone to if the roles were reversed.

None of this is about chasing complexity for its own sake. It's the opposite, the goal is always simplicity that lasts, built on decisions made carefully the first time. That range across the stack, paired with a habit of caring about the details others skip, is what lets me deliver software people can actually build on top of, not just around.
